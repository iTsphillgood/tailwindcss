# Developer Onboarding & Architectural Overview

Welcome to the Tailwind CSS repository! This document is designed to help you get up to speed with the codebase, understand the architecture, and start contributing.

## 1. Project Overview

This repository houses the source code for Tailwind CSS (specifically the next major version, v4.0). It is a monorepo that combines a high-performance Rust core (Oxide) with a comprehensive TypeScript ecosystem.

**Key Goals:**

- **Performance:** Moving computationally expensive tasks to Rust.
- **Modularity:** splitting the project into smaller, focused packages.
- **Compatibility:** Maintaining a smooth developer experience across different build tools (Vite, PostCSS, CLI).

## 2. Repository Structure

The project is organized as a monorepo using `pnpm` workspaces and `turbo` for build orchestration.

### Top-Level Directories

- **`crates/`**: Contains the Rust source code.
- **`packages/`**: Contains the TypeScript/JavaScript packages.
- **`integrations/`**: Contains integration tests ensuring Tailwind works correctly with various frameworks and tools.
- **`playgrounds/`**: (Likely) contains sandbox environments for testing changes manually.

### `crates/` (Rust Core)

- **`oxide/`**: The heart of the new engine. It handles:
  - File scanning and globbing.
  - Candidate extraction (finding class names in files).
  - CSS generation logic.
- **`node/`**: A N-API wrapper around `oxide` to expose its functionality to Node.js environments. This allows the TypeScript packages to call into the Rust core.
- **`classification-macros/`**: Proc-macros used within the Rust codebase.

### `packages/` (TypeScript Ecosystem)

- **`tailwindcss/`**: The main entry point for the library. It handles:
  - CSS Parsing and AST manipulation.
  - CSS-in-JS logic (e.g., `@apply`, `@theme`).
  - Interfacing with the Rust core (via `@tailwindcss/oxide`).
- **`@tailwindcss/oxide`**: The Node.js binding package (built from `crates/node`).
- **`@tailwindcss-cli/`**: The standalone Command Line Interface.
- **`@tailwindcss-vite/`**: The Vite plugin.
- **`@tailwindcss-postcss/`**: The PostCSS plugin for backward compatibility and integration with existing PostCSS chains.
- **`@tailwindcss-node/`**: Node.js specific utilities.
- **`@tailwindcss-browser/`**: Browser runtime (likely for CDN/runtime usage).

## 3. Architecture & Data Flow

### The "Oxide" Engine

The core philosophy is to offload heavy lifting to Rust. The `oxide` crate is responsible for scanning files and extracting potential Tailwind class names ("candidates").

1.  **Input**: Source files (HTML, JS, etc.) and CSS files.
2.  **Scanning**: `oxide` scans these files efficiently.
3.  **Extraction**: It identifies strings that look like Tailwind utility classes.
4.  **Processing**: The TypeScript layer (`packages/tailwindcss`) receives these candidates and uses the Design System to generate the corresponding CSS.

### The TypeScript Layer

The `tailwindcss` package acts as the orchestrator.

- It parses the input CSS (using a custom parser or Lightning CSS).
- It handles directives like `@tailwind`, `@apply`, `@theme`, and `@variant`.
- It maintains the state of the "Design System" (theme values, variants, utilities).
- It calls into `oxide` to get candidates but performs the final AST transformation and CSS generation.

## 4. Developer Workflow

### Prerequisites

- **Node.js**: (Check `.nvmrc` or `package.json` engines).
- **pnpm**: Used for package management.
- **Rust**: Required to build the `crates/`.

### Setup

1.  Install dependencies:
    ```bash
    pnpm install
    ```
2.  Build the project (including Rust crates):
    ```bash
    pnpm build
    ```

### Running Tests

- **JavaScript/TypeScript Tests**:
  ```bash
  pnpm test
  # or specifically for integrations
  pnpm test:integrations
  ```
- **Rust Tests**:
  ```bash
  cargo test
  ```

### Development

- **Dev Mode**:
  ```bash
  pnpm dev
  ```
  This will likely run `turbo dev`, watching for changes in both Rust and TS packages.

## 5. Key Technologies

- **Rust**: For performance-critical paths.
- **NAPI-RS**: For bridging Rust and Node.js.
- **TypeScript**: For the majority of the logic and tooling integration.
- **Vitest**: For unit and integration testing.
- **Turbo**: For monorepo task management.
- **PostCSS / Lightning CSS**: For CSS parsing and transformation.

## 6. Contribution Tips

- **Start Small**: Pick an issue related to a specific package (e.g., a bug in the CLI or a missing utility).
- **Check Integrations**: If you change core logic, run the integration tests to ensure you haven't broken Vite or PostCSS support.
- **Rust vs. TS**: If you are working on scanning or performance, look at `crates/oxide`. If you are working on CSS generation rules or plugins, look at `packages/tailwindcss`.
